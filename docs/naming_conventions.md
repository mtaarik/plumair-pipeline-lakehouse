# **Project Naming Conventions**

This document outlines the strict naming conventions used across the entire data platform, including infrastructure, streaming, storage, and transformation layers.

## **1. General Principles**

* **Language**: English is mandatory for all code, tables, columns, and infrastructure components.
* **Case Sensitivity**:
    * **`snake_case`**: Exclusively for Data objects (Schemas, Tables, Columns, dbt models).
    * **`kebab-case`**: Exclusively for Infrastructure objects (Docker containers, Networks, Kafka topics).
* **Avoid Reserved Words**: Do not use standard SQL or Python reserved keywords (e.g., `select`, `date`, `time`, `value`).

---

## **2. Infrastructure & Streaming**

### **Docker Components**
* **Pattern**: `<project>-<service>`
* **Examples**:
    * `plumair-kafka-broker`
    * `plumair-trino-coordinator`

### **Kafka Topics**
* **Pattern**: `<domain>-<entity>-<status>`
* **Rules**:
    * `<domain>`: The business domain (e.g., `iot`, `system`).
    * `<entity>`: The object generating the event (e.g., `stations`, `readings`).
    * `<status>`: The state of the data (e.g., `raw`, `alert`).
* **Examples**:
    * `iot-station-readings-raw` (Incoming hourly sensor telemetry)
    * `iot-emissions-alert` (Real-time threshold breaches)

## **3. Data Lakehouse Models (dbt & Iceberg)**

The data architecture follows the Medallion architecture (Bronze, Silver, Gold), orchestrated via dbt.

### **Bronze Layer (Raw Data)**
* **Schema**: `bronze`
* **Pattern**: `src_<source_system>_<entity>`
* **Rules**: Data is appended exactly as received from Kafka/NiFi or Batch files. No renaming or casting.
* **Examples**: 
    * `src_kafka_station_readings`
    * `src_static_stations`

### **Silver Layer (Cleaned & Conformed)**
* **Schema**: `silver`
* **Staging Pattern**: `stg_<source_system>_<entity>` (Light transformations: casting, renaming, basic deduplication).
* **Intermediate Pattern**: `int_<entity>_<verb>` (Complex business logic and joins).
* **Examples**:
    * `stg_kafka_station_readings`
    * `int_sensors_deduplicated`

### **Gold Layer (Aggregated & Business-Ready)**
* **Schema**: `gold`
* **Pattern**: `<category>_<entity>`
* **Rules**: Models optimized for Tableau reporting.
* **Categories**:
    * `dim_`: Dimension tables (e.g., `dim_monitoring_stations`).
    * `fct_`: Fact tables for transactional/event data (e.g., `fct_hourly_emissions`).
    * `mart_`: Highly aggregated business tables (e.g., `mart_city_daily_summary`).

## **4. Column & IoT Specific Conventions**

### **Time and Dates (Critical for IoT)**
* **Dates**: Must end with `_date` (Format: `YYYY-MM-DD`).
* **Timestamps**: Must end with `_at` or `_ts` and always include the timezone (UTC).
    * Example: `recorded_at`, `ingested_ts`

### **Measures and Metrics**
* Always include the unit of measurement as a suffix for clarity.
* **Pattern**: `<metric>_<unit>`
* **Examples**:
    * `pm25_ugm3` (Micrograms per cubic meter)
    * `co_mgm3` (Milligrams per cubic meter)
    * `nox_ppb` (Parts per billion)

### **Booleans and Flags**
* Must be prefixed with `is_`, `has_`, or `does_`.
* **Example**: `is_alert_triggered`

### **Primary, Surrogate, and Foreign Keys**
* **Primary/Surrogate Keys**: Must end with `_id`.
    * Example: `station_id`
* **Foreign Keys**: Must match the primary key name of the target table.

### **Metadata Columns**
* Technical columns generated by the pipeline must be prefixed with `_meta_`.
* **Examples**:
    * `_meta_loaded_at` (When the row was inserted).
    * `_meta_kafka_offset` (Original offset from the stream).
    * `_meta_missing_sensors_count` (Count of missing metrics/NaN values for the given hour).
